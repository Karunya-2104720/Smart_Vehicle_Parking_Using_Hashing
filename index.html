1. Why Use Modulo (% 11)?

A car key like 1021 cannot fit directly into 11 bays (numbered 0 to 10). Modulo arithmetic compresses any integer key into the finite range $[0, 10]$:

index = key % 11

We choose 11 because prime table sizes significantly reduce harmonic collisions when keys share common divisors!

2. Why Collisions Happen (Pigeonhole Principle)

If you have 11 slots and thousands of cars in a city, by the Pigeonhole Principle, multiple keys MUST yield the exact same remainder:

15 % 11 = 4  |  26 % 11 = 4  |  37 % 11 = 4

A collision is not a flaw in the system—it is a mathematical certainty that every hash table must be engineered to resolve.

3. Linear Probing & Primary Clustering

If slot $h$ is taken, check $(h+1)\%11$, then $(h+2)\%11$, and so on.

index = (hash(key) + i) % 11

The Flaw: Creates Primary Clustering. Contiguous blocks of occupied slots grow longer and longer, like a traffic jam where every new car gets stuck behind the previous ones.

4. Quadratic Probing & Secondary Clustering

Increases step size quadratically $(i^2 = 1, 4, 9, 16...)$ to jump cleanly over local clusters:

index = (hash(key) + i²) % 11

The Catch: Any two keys that share the exact same initial hash $h(k)$ will probe the exact same sequence (Secondary Clustering).

5. Double Hashing (True Uniform Probing)

Applies a secondary hash function $h_2(key) = 7 - (key \pmod 7)$ as a key-specific step multiplier:

index = (h1(key) + i × h2(key)) % 11

Even if two cars have the same $h_1$, their step size $h_2$ is almost always completely different! This virtually eliminates clustering.

6. The Tombstone / Deleted Slot Dilemma

Why can't we simply set a slot back to EMPTY when a car leaves?

If Car B was inserted past Slot 9 into Slot 10, resetting Slot 9 to EMPTY causes future searches for Car B to stop at Slot 9 and fail!

By marking it as a 🪦 TOMBSTONE, searches know to continue past it, while new car insertions can safely reclaim the bay.

7. Load Factor (α) & The Performance Cliff

Defined as $\alpha = \frac{\text{Occupied Slots}}{\text{Total Slots}}$. In our parking lot:

Load Factor = 7 / 11 = 0.636 (63.6%)

For open addressing, expected search probe length is approximately $\frac{1}{1 - \alpha}$. When $\alpha > 0.75$, collisions skyrocket! Real databases trigger table resizing (re-hashing) at $\alpha \approx 0.7$.

8. Open Addressing vs Separate Chaining

Open Addressing (what we implement here) keeps all records strictly inside the fixed 11 slots without allocating linked lists or extra memory pointers.

Max items = 11 | Memory locality: Cache-friendly

Separate Chaining would allow stacking multiple cars on top of each other using linked lists, but open addressing simulates true physical single-car parking bays!
